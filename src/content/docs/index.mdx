Documentación interna de la **plataforma Master Drilling**: la aplicación web con la que la
empresa administra Recursos Humanos, la mesa de ayuda y la propia plataforma. Esta documentación
es privada; contiene detalles de infraestructura y seguridad que no deben salir de aquí.

## Cómo está construida

Un **monorepo** (`master-drilling-release`) con dos aplicaciones independientes:

| | `laravel-api-kit` | `nuxt-app-kit` |
|---|---|---|
| Rol | API REST | Interfaz web (SPA) |
| Stack | PHP 8.4 · Laravel 13 · Sanctum (tokens) | Nuxt 4 (`ssr: false`) · Vue 3 · Nuxt UI |
| Datos | MySQL 8.4 · archivos en AWS S3 | — |
| Dominio | `api.mdmexico.online` | `mdmexico.online` |

En producción todo corre en **un servidor AWS EC2 con Docker**, detrás de **Cloudflare**. Las
imágenes se construyen en **GitHub Actions** y el servidor solo las descarga. Los detalles están
en [Deploy → Visión general](/deploy/).

Cada sección separa tres tipos de página:

- **Referencia**: cómo está hecho algo y por qué (arquitectura, infraestructura, variables).
- **Guías**: pasos para lograr algo concreto (actualizar, hacer rollback, restaurar un respaldo).
- **Estado**: lo que falta o no se ha probado. Se actualiza en cuanto cambia algo.

## Convenciones

- Los comandos indican **dónde se ejecutan**: tu PC, el servidor (por SSH) o GitHub.
- En el servidor, todos los comandos de Docker van con `sudo` y se ejecutan en `/opt/md/deploy`.
- Los valores secretos nunca aparecen en esta documentación; se indica dónde viven.

:::caution[Regla de oro]
Si un procedimiento de esta documentación ya no coincide con lo que hay en el servidor o en el
repo, **corrige la documentación en el mismo cambio**. Una guía desactualizada es peor que no
tener guía.
:::
