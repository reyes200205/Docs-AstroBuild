import { Steps } from '@astrojs/starlight/components';

Al terminar tendrás la API en `http://localhost:8000`, el frontend en `http://localhost:3000` y una
base de datos local con los catálogos, los roles y un usuario administrador.

Los comandos son para **PowerShell** o la terminal de Laragon (*Menu → Terminal*). Calcula
alrededor de una hora la primera vez.

## 1. Laragon

<Steps>

1. **Instala Laragon** desde [laragon.org](https://laragon.org) en `C:\laragon` (la ruta por
   defecto).

2. **Comprueba las versiones** que necesita el proyecto. Cada componente vive en una carpeta de
   `C:\laragon\bin\` y se elige desde el menú de Laragon (clic derecho en la ventana o en el ícono
   de la bandeja):

   | Componente | Versión | Dónde se elige |
   |---|---|---|
   | PHP | **8.4** (NTS, x64) | *Menu → PHP → Version* |
   | MySQL | **8.4** | *Menu → MySQL → Version* |
   | Node.js | **22** | *Menu → Node.js → Version* |

   Si falta una versión: descarga el ZIP oficial (PHP desde [windows.php.net](https://windows.php.net/download/),
   variante *Non Thread Safe x64*; MySQL y Node desde sus sitios), descomprímelo dentro de
   `C:\laragon\bin\php\`, `bin\mysql\` o `bin\nodejs\` y elígelo en el menú.

3. **Agrega Laragon al PATH** para usar `php`, `composer`, `mysql` y `node` desde cualquier
   terminal: *Menu → Tools → Path → Add Laragon to Path*. Cierra y vuelve a abrir la terminal.

4. **Extensiones de PHP**. Comprueba que estén activas:

   ```powershell
   php -m
   ```

   Deben aparecer: `bcmath`, `curl`, `exif`, `fileinfo`, `gd`, `intl`, `mbstring`, `openssl`,
   `pdo_mysql`, `pdo_sqlite`, `sodium`, `xsl` y `zip`. Las que falten se activan en
   *Menu → PHP → Extensions*. `pdo_sqlite` la usan las pruebas automáticas.

5. **Arranca los servicios**: botón **Start All**. Deben quedar en verde MySQL y Mailpit (nginx
   también arranca, pero el proyecto no lo usa).

6. **Verifica**:

   ```powershell
   php -v; composer -V; node -v; mysql --version
   ```

   PHP `8.4.x`, Composer `2.x`, Node `v22.x` y MySQL `8.4.x`.

</Steps>

## 2. pnpm

El frontend fija su versión de pnpm en `package.json` (`"packageManager": "pnpm@11.22.0"`).
Corepack, que viene con Node 22, descarga y usa esa versión automáticamente:

```powershell
corepack enable
```

Si falla por permisos, abre la terminal como administrador y repítelo. Alternativa:
`npm install -g pnpm@11.22.0`.

## 3. Acceso al repositorio

<Steps>

1. **Cuenta de GitHub** con acceso al repo `reyes200205/master-drilling-release` (pídeselo al
   dueño del repo).

2. **Identidad de Git** (la que aparecerá en tus commits):

   ```powershell
   git config --global user.name "Tu Nombre"
   ```

   ```powershell
   git config --global user.email "tu-correo@ejemplo.com"
   ```

3. **Llave SSH** para GitHub, si todavía no tienes una:

   ```powershell
   ssh-keygen -t ed25519 -C "tu-correo@ejemplo.com"
   ```

   ```powershell
   Get-Content $HOME\.ssh\id_ed25519.pub
   ```

   Copia la salida en GitHub → *Settings → SSH and GPG keys → New SSH key*. Comprueba:

   ```powershell
   ssh -T git@github.com
   ```

4. **Clona** el repo (en la carpeta que prefieras) y cámbiate a `develop`, que es la rama de
   trabajo ([Flujo de Git](/development/git-workflow/)):

   ```powershell
   git clone git@github.com:reyes200205/master-drilling-release.git
   ```

   ```powershell
   cd master-drilling-release; git checkout develop
   ```

</Steps>

## 4. Base de datos

Laragon trae MySQL con el usuario `root` **sin contraseña**, que es justo lo que espera
`laravel-api-kit/.env.example`. Crea la base `md`:

```powershell
mysql -u root -e "CREATE DATABASE md CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
```

También puedes hacerlo desde HeidiSQL (*Menu → Database*): clic derecho en la conexión →
*Create new → Database*, nombre `md`, cotejamiento `utf8mb4_unicode_ci`.

## 5. Backend (`laravel-api-kit`)

<Steps>

1. **Dependencias**:

   ```powershell
   cd laravel-api-kit
   ```

   ```powershell
   composer install
   ```

2. **`.env`** a partir de la plantilla, y su llave:

   ```powershell
   cp .env.example .env
   ```

   ```powershell
   php artisan key:generate
   ```

   Los valores de la plantilla ya sirven para Laragon:

   | Variable | Valor | Por qué |
   |---|---|---|
   | `APP_URL` | `http://localhost:8000` | Donde escucha `php artisan serve` |
   | `FRONTEND_URL` | `http://localhost:3000` | Enlaces en correos y notificaciones |
   | `DB_*` | `127.0.0.1`, `3306`, `md`, `root`, sin contraseña | El MySQL de Laragon |
   | `FILESYSTEM_DISK` | `public` | Los archivos se guardan en `storage/app/public` |
   | `MAIL_HOST` / `MAIL_PORT` | `127.0.0.1` / `1025` | El Mailpit de Laragon |

   Las llaves de IA (`GROQ_API_KEY`), Firebase y AWS son opcionales: sin ellas esas funciones
   quedan apagadas.

   :::danger[Nunca uses secretos de producción en local]
   Ni las credenciales del bucket de S3 de producción ni sus llaves. Si necesitas probar S3, usa
   un bucket de pruebas.
   :::

3. **Tablas y datos de desarrollo**:

   ```powershell
   php artisan migrate --seed
   ```

   Fuera de producción, `--seed` ejecuta `DevelopmentSeeder`: módulos, roles, permisos y
   catálogos, más los departamentos y un **super admin** (el de
   `database/seeders/Development/UsersSeeder.php`, contraseña `password`).

4. **Enlace del disco `public`** (fotos, documentos, adjuntos):

   ```powershell
   php artisan storage:link
   ```

5. **Arranca la API**:

   ```powershell
   php artisan serve
   ```

   Deja esta terminal abierta. Comprueba en el navegador `http://localhost:8000/api/v1/ping`
   (responde `{"message":"Pong"}`) y `http://localhost:8000/docs/api`.

</Steps>

## 6. Frontend (`nuxt-app-kit`)

En **otra** terminal, desde la raíz del repo:

<Steps>

1. **Dependencias**:

   ```powershell
   cd nuxt-app-kit
   ```

   ```powershell
   pnpm install
   ```

   `pnpm -v` debe mostrar `11.22.0`.

2. **`.env`**:

   ```powershell
   cp .env.example .env
   ```

   `NUXT_PUBLIC_API_URL=http://localhost:8000` (sin `/` al final). `NUXT_PUBLIC_TURNSTILE_SITE_KEY`
   se deja vacía: en local el buzón público `/ideas` funciona sin el captcha.

3. **Arranca el frontend**:

   ```powershell
   pnpm dev
   ```

   Abre `http://localhost:3000` e inicia sesión con el super admin del paso 5.3.

</Steps>

## 7. Procesos opcionales

Algunas funciones necesitan procesos extra, cada uno en su propia terminal dentro de
`laravel-api-kit`:

| Proceso | Comando | Lo necesitas para |
|---|---|---|
| Worker de colas | `php artisan queue:work` | Notificaciones, correos en cola, botones *Ejecutar* y *Simular* de Tareas Programadas |
| Scheduler | `php artisan schedule:work` | Que las tareas programadas corran a su hora |

## Problemas frecuentes

| Síntoma | Causa | Solución |
|---|---|---|
| `could not find driver` | `pdo_mysql` (o `pdo_sqlite` en las pruebas) apagada | *Menu → PHP → Extensions* |
| `SQLSTATE[HY000] [1049] Unknown database 'md'` | No se creó la base | Paso 4 |
| `SQLSTATE[HY000] [2002]` | MySQL no está corriendo | *Start All* en Laragon |
| `php` o `composer` no se reconocen | Laragon no está en el PATH | Paso 1.3 y abre una terminal nueva |
| Se usa otra versión de PHP | El PATH apunta a una versión vieja | *Menu → PHP → Version → 8.4* y repite *Add Laragon to Path* |
| El login responde `401` con el super admin | No se ejecutaron los seeders | `php artisan migrate --seed` |
| Error de CORS en el navegador | `CORS_ALLOWED_ORIGINS` definida sin `http://localhost:3000` | Quítala del `.env` (sin definir permite todo) o agrégale ese origen |
| El frontend llama a otra URL | `NUXT_PUBLIC_API_URL` mal escrita | Corrige el `.env` de Nuxt y reinicia `pnpm dev` |
| El puerto 8000 está ocupado | Otro proceso lo usa | `php artisan serve --port=8001` y cambia `NUXT_PUBLIC_API_URL` y `APP_URL` |
| Las imágenes subidas no se ven | Falta el enlace de `storage` | `php artisan storage:link` |
| `ERR_PNPM_BAD_PM_VERSION` o versión distinta de pnpm | Corepack apagado | `corepack enable` |
| No llegan los correos | Se envían a Mailpit, no a tu bandeja | Ábrelos en `http://localhost:8025` |
