---
title: Usuario actual (Me)
description: Documentación del endpoint para obtener el perfil, roles, permisos y configuración del usuario autenticado.
---

import { Badge, Tabs, TabItem } from '@astrojs/starlight/components';

Devuelve la información del usuario autenticado a partir del token de acceso (**Bearer Token**). Proporciona los datos de su perfil, el estado de cambio de contraseña, puesto asignado, roles, permisos filtrados por módulos activos y los recorridos guiados completados.

---

## Endpoint

<div style="display: flex; align-items: center; gap: 12px; margin: 16px 0; font-family: monospace; font-size: 1.1rem;">
  <Badge text="GET" variant="note" size="large" />
  <span>/api/v1/me</span>
</div>

| Entorno | URL Base | Endpoint Completo |
|---|---|---|
| **Producción** | `https://api.mdmexico.online` | `https://api.mdmexico.online/api/v1/me` |
| **Local / Dev** | `http://localhost:8000` | `http://localhost:8000/api/v1/me` |

:::tip[Endpoint Protegido]
Requiere un token de autenticación válido obtenido en el [Login](/api-docs/auth/login/). Debe enviarse en el encabezado `Authorization`.
:::

---

## Parámetros de la solicitud (Request)

### Encabezados (Headers)

| Encabezado | Tipo | Valor | Obligatorio | Descripción |
|---|---|---|---|---|
| `Authorization` | String | `Bearer <token>` | **Sí** | Token personal de acceso Sanctum. |
| `Accept` | String | `application/json` | **Sí** | Formato de respuesta esperado. |

*(Este endpoint no recibe parámetros en la URL ni en el cuerpo de la petición).*

## Respuestas (Responses)

### <Badge text="200 OK" variant="success" /> Perfil obtenido exitosamente

Retorna los datos del usuario asociado al token enviado.

```json
{
  "success": true,
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Alejandro Rentería",
    "email": "alejandro@mdmexico.online",
    "avatar_url": "https://s3.amazonaws.com/bucket/avatars/user_1.jpg",
    "email_verified_at": "2026-01-10T12:00:00.000000Z",
    "password_change_required": false,
    "position": "Software Engineer",
    "roles": {
      "admin": "Administrador"
    },
    "permissions": [
      "view_dashboard",
      "manage_employees",
      "export_reports"
    ],
    "modules": [
      {
        "id": "rh",
        "name": "Recursos Humanos",
        "enabled": true
      },
      {
        "id": "kiosk",
        "name": "Pantallas Kiosko",
        "enabled": true
      }
    ],
    "completed_tours": "{\"welcome\":\"1.0\",\"dashboard\":\"1.2\"}",
    "created_at": "2025-08-01T09:00:00.000000Z",
    "updated_at": "2026-03-15T16:20:00.000000Z"
  }
}
```

#### Descripción de los campos del objeto `data`

| Campo | Tipo | Descripción y Reglas de Negocio |
|---|---|---|
| `id` | `integer` | Identificador único del usuario. |
| `name` | `string` | Nombre completo del usuario. |
| `email` | `string` | Correo electrónico principal. |
| `avatar_url` | `string \| null` | URL de la imagen de perfil del usuario (o `null` si no tiene). |
| `email_verified_at` | `string` | Fecha y hora en formato ISO 8601 de verificación de correo. |
| `password_change_required` | `boolean` | **Crítico:** Si es `true`, la UI debe bloquear la navegación y redirigir exclusivamente a la pantalla de cambio obligatorio de contraseña. |
| `position` | `string \| null` | Puesto del empleado vinculado. Si es `null`, la interfaz debe utilizar los roles asignados para mostrar la descripción. |
| `roles` | `object` | Diccionario con los identificadores y nombres de los roles que posee el usuario. |
| `permissions` | `array<string>` | Lista de permisos efectivos. **Nota:** No incluye permisos de módulos o funcionalidades que estén apagadas en el sistema, permitiendo que la UI oculte pantallas automáticamente sin lógica extra. |
| `modules` | `array<object>` | Lista de módulos del sistema disponibles para el usuario y su estado. |
| `completed_tours` | `string` | Objeto serializado `{ tour_key: version }` con los recorridos guiados que el usuario ya ha visualizado. |
| `created_at` | `string` | Fecha de creación del registro de usuario. |
| `updated_at` | `string` | Fecha de última modificación del usuario. |

### Códigos de Error

#### <Badge text="401 Unauthorized" variant="danger" /> No autenticado

Ocurre si no se envía la cabecera `Authorization`, si el token no tiene el formato correcto, si ha expirado o si fue revocado tras un cierre de sesión.

```json
{
  "message": "Unauthenticated."
}
```
